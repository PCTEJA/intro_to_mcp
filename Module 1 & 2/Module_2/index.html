The Three Core Primitives

Tools, Resources, and Prompts - the building blocks of MCP

🔧

Tools

Functions that clients can invoke to perform actions

Click to explore →

Tool Characteristics

  • Stateless operations
  • Input/output schemas defined
  • Can modify external state
  • Provide immediate results
{
  "name": "calculator",
  "description": "Perform math",
  "inputSchema": {
    "type": "object",
    "properties": {
      "expression": {"type": "string"}
    }
  }
}
📚

Resources

Data sources that provide contextual information

Click to explore →

Resource Characteristics

  • Read-only access patterns
  • Can be static or dynamic
  • Support subscriptions for updates
  • Structured data with schemas
{
  "uri": "database://schema",
  "name": "DB Schema",
  "mimeType": "application/json",
  "description": "Current tables"
}
💬

Prompts

Template prompts for AI interactions

Click to explore →

Prompt Characteristics

  • Parameterized templates
  • Context-aware suggestions
  • Support for arguments
  • Reusable across sessions
{
  "name": "code_review",
  "description": "Generate review",
  "arguments": [{
    "name": "code",
    "description": "Code to review"
  }]
}

Communication Flow

Step-by-step journey through the MCP protocol

1

Initialize Connection

2

Discover Capabilities

{"method": "list", "params": {"type": "tools"}}
3

Invoke Operations

Client calls tools, reads resources, or uses prompts

{"method": "tools/call", "params": {...}}
4

Receive Results

Server responds with requested data or results

{"result": {"content": [...]}}
5

Handle Updates

Server sends notifications for resource changes

{"method": "notifications/...", "params": {...}}

Application Layer

The top layer where MCP primitives are exposed and business logic resides.

  • Tools: Executable functions with defined schemas
  • Resources: Data sources with read access
  • Prompts: Parameterized templates

Protocol Layer

JSON-RPC 2.0 provides the communication framework for MCP.

  • Requests: Method calls with parameters
  • Responses: Results or errors
  • Notifications: One-way messages

Transport Layer

Multiple transport methods support different deployment scenarios.

  • stdio: Process communication
  • SSE: Server-sent events over HTTP
  • WebSocket: Bidirectional real-time
